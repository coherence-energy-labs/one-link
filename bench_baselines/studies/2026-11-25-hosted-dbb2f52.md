# First hosted paired study: retained inconclusive result

The first complete hosted study correctly blocked performance acceptance as
**INCONCLUSIVE**. It does not establish that the changed native artifact meets
the 5% throughput-regression limit. This record explains a sampling correction;
it does not replace, discard or reclassify the original observations.

## What the observations establish

The following intervals are the original gate's deterministic paired-median
bootstrap intervals. They are candidate/baseline throughput ratios; acceptance
for these metrics requires the lower bound to be at least 0.95.

| Metric | Median ratio | Original 95% interval | Result |
| --- | ---: | ---: | --- |
| Chunk-store write, 32 × 64 KiB | 0.95211 | 0.79951–1.24451 | Inconclusive |
| Chunk-store write, 128 × 64 KiB | 1.06507 | 0.73586–1.44617 | Inconclusive |
| WAL, 128 × 4 KiB | 1.03123 | 0.92428–1.37754 | Inconclusive |
| WAL, 128 × 64 KiB | 0.97618 | 0.88837–2.58593 | Inconclusive |
| QUIC sequential, 16 KiB × 200 | 0.94758 | 0.90089–0.99181 | Inconclusive |
| QUIC sequential, 64 KiB × 200 | 1.02985 | 0.92619–1.10088 | Inconclusive |
| QUIC sequential, 256 KiB × 50 | 0.97034 | 0.91245–1.00028 | Inconclusive |
| QUIC sequential, 1024 KiB × 20 | 0.98805 | 0.94605–1.04991 | Inconclusive |

Each QUIC metric had only **three timed batches per process**, with no explicit
same-connection warm-up. The 16 KiB process medians were about 5.5–6.1 ms per
batch. The storage metrics had only **five timed batches per process**. For the
128-chunk store workload, many batches took about 32 ms but the slowest retained
batch took 208 ms. The 64 KiB WAL workload included a 210 ms batch. These
observations demonstrate substantial within-study variability and short
measurement windows; they do not identify the cause of individual stalls.

The **16 KiB QUIC candidate was slower in all five matched pairs**. Its median
throughput reduction was 5.24%. It must not be dismissed as runner noise: the
interval crosses the 5% acceptance boundary, so this study cannot determine
whether the reduction exceeds the permitted limit.

The native QUIC, WAL and chunk-store source files did not change between the
compared source trees. Their dependency graph did change, including:

| Dependency | Baseline | Candidate |
| --- | --- | --- |
| quinn-proto | 0.11.16 | 0.11.19 |
| quinn-udp | 0.5.15 | 0.5.16 |
| tokio | 1.53.1 | 1.54.1 |
| rustls | 0.23.45 | 0.23.46 |

Dependency behavior and whole-artifact code layout are plausible factors;
neither is established as the cause. Shared-runner scheduling and storage
variability are also plausible. The security dependency updates remain intact.

## Predeclared next measurement plan

The next CI study uses a distinct, recorded `ci` sampling profile:

1. Exactly **20 complete pairs**, alternating candidate/base and
   base/candidate so each arm starts ten pairs. Pair count is fixed before
   observing results; the runner rejects a different count for this profile.
2. **31 timed batches** per WAL, chunk-store write and QUIC metric. All raw
   durations and byte counts are retained, including stalls. Storage still
   includes directory/store creation, writes, flush, close and cleanup.
3. **Three untimed QUIC warm-up batches** on the same established connection,
   followed by measured batches carrying **at least 16 MiB** of response
   payload. Sequential request counts for 16/64/256/1024 KiB become
   1024/256/64/20; the existing 20 MiB largest batch remains 20 MiB. Parallel
   request counts become 16 × 16 at 64 KiB and 8 × 8 at 256 KiB. The actual
   native stream-lane count remains explicitly recorded in each metric. Server
   helper calls are grouped within the existing 8,192-request native bound on
   the same connection; neither the limit nor the planned request count changes.
4. Both artifacts use the same profile and harness. The manifest and every
   result record the profile; mismatched or missing child profiles fail the
   paired runner. Metric names record changed batch dimensions, so longer
   workloads cannot be mistaken for the original short batches.
5. The same **5% general / 12% named crypto-class limits**, 95% interval method
   and PASS/FAIL/INCONCLUSIVE decisions remain in effect. All 20 pairs enter the
   gate. There is no automatic retry or outcome-dependent stopping rule.

This increases the number of separate process pairs and the time spent on
each noisy component. It does not guarantee a passing outcome or prove a fixed
amount of precision on a shared host. A subsequent inconclusive study remains
blocked and may require a controlled runner or a targeted implementation and
dependency investigation. The ordinary `quick` profile remains a build/local
smoke test, with no CI performance-acceptance claim.
